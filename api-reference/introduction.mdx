La API de ImpactU es una API REST que devuelve información científica y académica en formato JSON: personas, productos, afiliaciones, fuentes, patentes, proyectos y entidades geográficas. La consulta es pública y de solo lectura. Con sesión, la API también permite administrar usuarios y cargar los archivos de las instituciones.

## URL base

```text
https://api.dev.impactu.colav.co
```

Todas las rutas de esta documentación se agregan a esa URL. Por ejemplo, `GET /search/works` se consulta en `https://api.dev.impactu.colav.co/search/works`.

## Formato de las respuestas

Las respuestas son JSON y tienen dos formas, según el tipo de endpoint.

<Tabs>
  <Tab title="Un recurso">
    Los endpoints que devuelven una sola entidad envuelven el resultado en `data` y agregan `meta`, con la misma forma que en los listados (`count` vale `1`).

    ```json
    {
      "data": { "...": "..." },
      "meta": {
        "count": 1,
        "page": 1,
        "size": 1,
        "db_response_time_ms": 25,
        "cursor": { "next": null, "previous": null }
      }
    }
    ```

  </Tab>
  <Tab title="Un listado">
    Los endpoints de búsqueda devuelven una lista en `data` y los datos de paginación en `meta`.

    ```json
    {
      "data": [ { "...": "..." } ],
      "meta": {
        "count": 1542618,
        "page": 1,
        "size": 10,
        "db_response_time_ms": 348,
        "cursor": { "next": "https://...", "previous": null }
      }
    }
    ```

  </Tab>
</Tabs>

Algunos endpoints devuelven el objeto sin envolver en `data`: los filtros disponibles, las afiliaciones relacionadas (de una afiliación o de una entidad geográfica), `/info` y `/info/quality`. Las exportaciones devuelven un archivo CSV o Excel.

## Convenciones de los listados

Los endpoints de búsqueda comparten estos parámetros de consulta.

<ParamField query="keywords" type="string">
  Texto de búsqueda. Se usa en las búsquedas desde caja de texto.
</ParamField>

<ParamField query="max" type="integer" default="10">
  Resultados por página, de 1 a 250.
</ParamField>

<ParamField query="page" type="integer" default="1">
  Número de página.
</ParamField>

<ParamField query="sort" type="string" default="citations_desc">
  Ordenamiento con el formato `campo_direccion`, donde la dirección es `asc` o
  `desc`. Los campos válidos dependen de la entidad y se describen en cada
  endpoint.
</ParamField>

<ParamField query="view" type="string" default="full">
  Nivel de detalle de la respuesta: `full` (todos los campos) o `summary` (solo
  los campos principales). Lo aceptan los listados y los detalles de las
  entidades, salvo la búsqueda y el detalle de entidades geográficas y las
  noticias.
</ParamField>

Además, cada listado tiene sus propios filtros. Todos aceptan varios valores separados por coma (por ejemplo, `years=2020,2026`), y las opciones válidas se consultan en el endpoint de filtros disponibles de cada entidad.

<Note>
  Si no envías `max`, `page` ni `sort`, se aplican `max=10`, `page=1` y
  `sort=citations_desc`. Si envías `max` y `page` sin `sort`, se aplica
  `sort=citations_desc`.
</Note>

## Datos y formatos

<AccordionGroup>
  <Accordion title="Fechas" icon="calendar">
    Las fechas se expresan en segundos Unix. En las fechas de fin, un valor `-1` indica que la relación sigue vigente.
  </Accordion>

  <Accordion title="Identificadores" icon="fingerprint">
    Cada entidad tiene su propio formato de identificador:

    | Entidad | Ejemplo |
    | --- | --- |
    | Institución | `03bp5hc83` (identificador ROR) |
    | Facultad | `03bp5hc83_20` |
    | Departamento | `03bp5hc83_2_21620003_3154` |
    | Grupo de investigación | `COL0001262` |
    | Persona | `0000000001` |
    | Producto, fuente | `6ab555045418a51e325f5303` |

  </Accordion>

  <Accordion title="Información por fuente" icon="layer-group">
    Muchos campos (nombres, citas, tipos, rankings) devuelven un elemento por cada fuente de información, con los campos `source` y `provenance`.
  </Accordion>
</AccordionGroup>

## Autenticación y límites

Los endpoints de consulta son públicos: no requieren autenticación y por ahora no tienen límite de solicitudes.

Requieren sesión la administración de usuarios (`/admin/users`), la gestión del API Key (`/users/{email}/apikey`), el estado de sesión (`/me`) y todas las cargas de archivos (`/submit/staff`, `/submit/ciarp`, `/submit/scienti` y `/submit/project`). La sesión es el JWT que [Iniciar sesión](/api-reference/auth/login) guarda en la cookie HttpOnly `access_token_cookie`.

- **Token CSRF.** Las solicitudes con sesión que no son `GET` (`POST`, `PUT`, `PATCH` y `DELETE`) deben enviar el encabezado `X-CSRF-TOKEN` con el valor de la cookie `csrf_access_token`, que también crea el inicio de sesión. Sin ese encabezado responden `401`.
- **Cuentas desactivadas.** Cada solicitud con sesión comprueba que la cuenta siga activa. Si un administrador la desactiva, o la cuenta ya no existe, el token deja de servir de inmediato y la solicitud responde `403`, aunque el token no haya vencido.

## Errores

Cuando una solicitud falla, la API responde con el código HTTP del caso y un mensaje en `error`:

| Código | Cuándo |
| --- | --- |
| `400` | Un parámetro es inválido: por ejemplo `max=0`, un `sort` mal formado, un campo de `fields` que no está permitido o un cuerpo JSON que no es un objeto. |
| `401` | Falta la sesión, el token no es válido o falta el encabezado `X-CSRF-TOKEN`. |
| `403` | La sesión no tiene permiso para la operación o la cuenta está desactivada. |
| `404` | La entidad no existe. |
| `409` | La operación choca con un registro existente, por ejemplo al crear un usuario. |
| `413` | El archivo supera el tamaño máximo. Solo en [Validar archivo de proyectos](/api-reference/submit/project), con un máximo de 10 MB. |
| `415` | El tipo de archivo no está permitido. Solo en [Enviar archivo SCIENTI](/api-reference/submit/scienti). |
| `422` | Al Excel de Staff o CIARP le faltan columnas o tiene columnas sin nombre. |
| `500` | Error inesperado del servidor. |
| `502` | No se pudo enviar el correo con las credenciales al crear un usuario, cambiar su correo o restablecer su contraseña. No se guarda ningún cambio, así que se puede reintentar. |

```json
{ "error": "The person with id 9999999999 does not exist." }
```

Los endpoints de autenticación, usuarios y carga de archivos responden con `{ "success": false, "msg": "..." }` en lugar de `error`. [Validar archivo de proyectos](/api-reference/submit/project) usa `error` para los problemas del archivo (`400` y `413`) y `msg` para los de sesión (`401` y `403`).

Los listados de una entidad que no existe (por ejemplo, los productos de un autor inexistente) responden `200` con la lista vacía.

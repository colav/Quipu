---
title: "Validar archivo de proyectos"
api: "POST https://api.dev.impactu.colav.co/submit/project"
description: "Valida un Excel de proyectos institucionales (formato v1.0) y devuelve un reporte detallado de errores y advertencias."
---

<Note>
  Requiere sesión activa. El JWT se lee desde la cookie `access_token_cookie`
  y la solicitud debe llevar el encabezado `X-CSRF-TOKEN`. Se envía como
  `multipart/form-data`. Este endpoint solo valida: no guarda el archivo.
</Note>

## Cuerpo de la solicitud

<ParamField body="file" type="file" required>
  Archivo Excel `.xlsx` con los proyectos institucionales. Un `.xls` se rechaza
  con un mensaje que pide guardarlo como `.xlsx`. Solo se lee la primera hoja,
  con una fila por proyecto. Si un proyecto tiene varios investigadores o
  fuentes de financiación, se separan con `;` en la misma celda, o se repite la
  fila con el mismo `codigo_proyecto`.
</ParamField>

## Límites

| Límite | Valor | Respuesta |
| --- | --- | --- |
| Tamaño del archivo | 10 MB | `413`, sin leer el archivo |
| Contenido descomprimido (un `.xlsx` es un zip) | 100 MB | `400` |
| Filas con datos | 20 000 | `400` |
| Problemas listados en `issues` | 500 | `200`, con `issues_truncated: true` y los conteos completos |

Un archivo vacío, dañado o que no es un Excel responde `400` con el motivo.

## Formato del archivo

La primera fila lleva los encabezados. Se reconocen aunque cambien las mayúsculas, las tildes o los espacios, o lleven el `*` con el que el documento del formato marca los obligatorios: `Código Proyecto*` es `codigo_proyecto`. Una columna que no es del formato se ignora con una advertencia, y una columna repetida es un error.

| Columna | Obligatoria | Descripción |
| --- | --- | --- |
| `codigo_proyecto` | ✅ | Identificador único del proyecto. No debe cambiar en futuras actualizaciones. |
| `titulo` | ✅ | Nombre completo del proyecto. |
| `fecha_inicio` | ✅ | Fecha de inicio: celda con formato de fecha, o texto `DD/MM/YYYY`. |
| `investigador_principal_id` | ✅ | Número de documento del investigador principal, sin espacios ni separadores. Debe coincidir con el formato de Staff. |
| `resumen` | Recomendada | Resumen o abstract del proyecto. Si falta la columna o el valor, se reporta una advertencia. |
| `objetivos` | — | Objetivos generales o específicos. |
| `tipo_proyecto` | — | Uno de: `investigación`, `extensión`, `regalías`, `innovación`, `consultoría`. |
| `estado` | — | Uno de: `propuesta`, `en ejecución`, `finalizado`, `suspendido`. |
| `fecha_fin` | — | Fecha de finalización, con el mismo formato que `fecha_inicio`. |
| `investigador_principal_institucion_id` | — | Código ROR de la institución del investigador principal: `03bp5hc83` o `https://ror.org/03bp5hc83`. |
| `investigadores_ids` | — | Documentos de los coinvestigadores, separados por `;`. |
| `valor_total` | — | Presupuesto total en COP: número entero, sin signos de moneda ni separadores de miles (ej. `50000000`). |
| `valor_especie_total` | — | Presupuesto en especie en COP, con el mismo formato. |
| `valor_fresco_total` | — | Presupuesto en recursos frescos en COP, con el mismo formato. |
| `fuente_financiacion_ids` | — | Códigos ROR o IDs de Wikidata (`Q12345`) de las entidades financiadoras, separados por `;`. |
| `instituciones_participantes_ids` | — | Códigos ROR o IDs de Wikidata de las instituciones aliadas, separados por `;`. |
| `codigo_minciencias` | — | Código del proyecto en MinCiencias / CvLAC / GrupLAC. |
| `codigo_bpin` | — | Código BPIN para proyectos de regalías o inversión pública. |
| `convocatoria` | — | Nombre o código de la convocatoria. |
| `regiones_ejecucion_id` | — | Códigos GeoNames de departamentos o regiones (el número o su URL), separados por `;`. |
| `unidad_academica_ids` | — | Códigos de las unidades académicas responsables, separados por `;`. Deben coincidir con el formato de Staff. |
| `grupos_id` | — | Códigos Scienti de los grupos de investigación, separados por `;`. |
| `productos_asociados_ids` | — | Identificadores de productos derivados (DOI, Handle DSpace, código MinCiencias, OpenAlex ID), separados por `;`. |

Los valores de catálogo se aceptan sin importar mayúsculas, tildes ni espacios extra; un valor fuera del catálogo es un error. Las filas en blanco se ignoran.

### Reglas entre campos

| Regla | Severidad |
| --- | --- |
| `fecha_fin` anterior a `fecha_inicio` | Error |
| Proyecto `finalizado` sin `fecha_fin` (si la columna existe) | Advertencia |
| Proyecto de `regalías` sin `codigo_bpin` | Advertencia |
| El investigador principal también está en `investigadores_ids` | Advertencia |
| `valor_total` distinto de `valor_especie_total` + `valor_fresco_total` (si los tres tienen valor) | Advertencia |
| Un valor repetido en una columna de lista | Advertencia |

Un proyecto repetido en varias filas puede variar en las columnas de lista. En las demás columnas, un valor distinto al de la primera fila del proyecto que tiene ese campo diligenciado es un error.

## Respuesta

<ResponseField name="data" type="object">
  Reporte de validación.
  <Expandable title="propiedades">
    <ResponseField name="schema_version" type="string">
      Versión del esquema de validación utilizado.
    </ResponseField>
    <ResponseField name="valid" type="boolean">
      `true` si el archivo no tiene errores (puede tener advertencias).
    </ResponseField>
    <ResponseField name="total_rows" type="integer">
      Número de filas con datos.
    </ResponseField>
    <ResponseField name="total_projects" type="integer | null">
      Número de proyectos únicos (por `codigo_proyecto`). `null` si hay errores
      de estructura, como una columna obligatoria faltante: en ese caso las
      filas no se validan.
    </ResponseField>
    <ResponseField name="errors_count" type="integer">
      Número de errores encontrados.
    </ResponseField>
    <ResponseField name="warnings_count" type="integer">
      Número de advertencias encontradas.
    </ResponseField>
    <ResponseField name="issues_truncated" type="boolean">
      `true` si hay más de 500 problemas: `issues` lista los primeros 500 y los
      conteos incluyen todos.
    </ResponseField>
    <ResponseField name="issues" type="object[]">
      Lista de problemas, ordenados por fila (primero los del archivo, sin fila)
      y luego por columna.
      <Expandable title="propiedades de cada problema">
        <ResponseField name="severity" type="string">
          `error` o `warning`.
        </ResponseField>
        <ResponseField name="code" type="string">
          Código del tipo de problema. Por ejemplo, `missing_column`,
          `unknown_column`, `required`, `recommended_missing`, `invalid_date`,
          `invalid_money`, `invalid_enum`, `invalid_date_range` o
          `conflicting_values`.
        </ResponseField>
        <ResponseField name="message" type="string">
          Descripción del problema.
        </ResponseField>
        <ResponseField name="row" type="integer | null">
          Número de la fila en Excel. `null` para los problemas del archivo
          (columnas faltantes, hojas de más).
        </ResponseField>
        <ResponseField name="column" type="string | null">
          Nombre de la columna afectada, si aplica.
        </ResponseField>
        <ResponseField name="value" type="string | null">
          Valor que causó el problema, si aplica.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

The search endpoints (`/search/...`) share the same way of querying. This guide shows you how to combine their parameters.

## The four building blocks of a query

| Block       | Parameter          | What it is for                  |
| ----------- | ------------------ | ------------------------------- |
| Text search | `keywords`         | Search by name or title         |
| Pagination  | `max`, `page`      | Go through the results in parts |
| Sorting     | `sort`             | Set the order of the results    |
| Filters     | Varies by entity   | Narrow down the results         |

<Steps>
  <Step title="Search by text">
    Use `keywords` to search by name or title. To combine words with OR, AND or NOT, see the [semantic search](/en/guides/semantic-search) guide.

    ```text
    GET /search/works?keywords=colombia
    ```

  </Step>

  <Step title="Paginate the results">
    Use `max` (1 to 250) and `page`. The response includes the total number of results in `meta.count` and the URL of the next page in `meta.cursor.next`.

    ```text
    GET /search/works?max=20&page=2
    ```

  </Step>

  <Step title="Sort">
    `sort` uses the format `field_direction`, where the direction is `asc` or `desc`.

    ```text
    GET /search/works?sort=year_desc
    ```

  </Step>

  <Step title="Filter">
    Each entity has its own filters. To send several values, separate them with commas.

    ```text
    GET /search/works?years=2020,2026&status=diamond,gold
    ```

  </Step>
</Steps>

## Sort fields by entity

| Endpoint                      | `sort` fields                           |
| ----------------------------- | --------------------------------------- |
| `/search/person`              | `citations`, `products`, `h`, `h5`      |
| `/search/works`               | `citations`, `alphabetical`, `year`     |
| `/search/affiliations/{type}` | `citations`, `products`, `h`, `h5`      |
| `/search/sources`             | `citations`, `products`, `alphabetical` |
| `/search/patents`             | `alphabetical`                          |
| `/search/projects`            | `alphabetical`                          |
| `/search/geo/{type}`          | `alphabetical`                          |

<Warning>
  The value of `sort` must have exactly one underscore (for example,
  `products_desc`). Values such as `products_count_desc` or `year:desc` return
  a 400 error.
</Warning>

<Note>
  If you don't send `max`, `page` or `sort`, `max=10`, `page=1` and
  `sort=citations_desc` apply. Patent and project lists can only be sorted
  by `alphabetical`, so send `sort=alphabetical_asc` or
  `sort=alphabetical_desc` with them.
</Note>

## Filters by entity

| Endpoint                                                                      | Filters                                                                                                                              |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `/search/works`                                                               | `years`, `product_types`, `status`, `topics`, `countries`, `authors_count`, `authors_ranking`, `groups_ranking`, `institutions_type` |
| `/search/affiliations/{type}`                                                 | `states`, `cities`, `groups_ranking`                                                                                                 |
| `/search/sources`                                                             | `source_types`, `scimago_quartiles`, `apc_range`, `status`, `publication_time`, `license_type`, `topics`                             |
| `/search/person`, `/search/patents`, `/search/projects`, `/search/geo/{type}` | No filters                                                                                                                           |

## Find the valid values

Products, affiliations and sources have an endpoint that returns the available options of each filter, with the number of results for each:

- [`GET /search/works/filters`](/en/api-reference/search/works-filters)
- [`GET /search/affiliations/{affiliation_type}/filters`](/en/api-reference/search/affiliations-filters)
- [`GET /search/sources/filters`](/en/api-reference/search/sources-filters)

These endpoints accept the same filters as the list. If you have already applied a filter, they only return the options that exist within that result. The `value` of each option is what you must send in the filter.

## Special formats

<AccordionGroup>
  <Accordion title="Ranges: years, apc_range and publication_time">
    They are sent as a minimum and a maximum separated by a comma.

    ```text
    years=2020,2026
    ```

  </Accordion>

  <Accordion title="Number of authors: authors_count">
    It accepts four formats:

    | Value | Meaning |
    | --- | --- |
    | `5` | Exactly 5 authors |
    | `5-` | 5 or more authors |
    | `-5` | Up to 5 authors |
    | `5-8` | From 5 to 8 authors |

  </Accordion>

  <Accordion title="Topics and product types">
    Use the `value` returned by the filters endpoint. In `topics` it is the OpenAlex URL of a domain, field, subfield or topic (for example, `https://openalex.org/T14483`; the details are in the next section) and in `product_types` it carries the source prefix (for example, `impactu_Artículo de revista`).
  </Accordion>
</AccordionGroup>

## Filter by domain, field, subfield or topic

Each product has an OpenAlex primary topic (`primary_topic`), which belongs to a four-level hierarchy. The `topics` filter accepts any of them, each with its own URL:

| Level    | In OpenAlex | Format                                | Example                                                        |
| -------- | ----------- | ------------------------------------- | -------------------------------------------------------------- |
| Domain   | domain      | `https://openalex.org/domains/{id}`   | `https://openalex.org/domains/2` (Social Sciences)             |
| Field    | field       | `https://openalex.org/fields/{id}`    | `https://openalex.org/fields/33` (Social Sciences)             |
| Subfield | subfield    | `https://openalex.org/subfields/{id}` | `https://openalex.org/subfields/3304` (Education)              |
| Topic    | topic       | `https://openalex.org/T{id}`          | `https://openalex.org/T14483` (Education and Teacher Training) |

A level includes everything below it: filtering by a domain returns the products of all its fields, subfields and topics. With the examples in the table, each level narrows the previous one:

```text
GET /search/works?topics=https://openalex.org/domains/2        810,297 products
GET /search/works?topics=https://openalex.org/fields/33        453,028 products
GET /search/works?topics=https://openalex.org/subfields/3304   102,372 products
GET /search/works?topics=https://openalex.org/T14483            22,593 products
```

The counts are from November 2026 and change with every data update.

<AccordionGroup>
  <Accordion title="Several values, even from different levels">
    Separate the values with commas. They are joined with **OR**, so the result includes the products of any of them. You can mix levels: this example asks for the products of the Health Sciences domain or of the Social Sciences field.

    ```text
    GET /search/works?topics=https://openalex.org/domains/4,https://openalex.org/fields/33
    ```

  </Accordion>

  <Accordion title="Together with other filters">
    `topics` is joined with **AND** to the other filters. This example asks for the products of the Social Sciences field published between 2020 and 2026:

    ```text
    GET /search/works?topics=https://openalex.org/fields/33&years=2020,2026
    ```

  </Accordion>

  <Accordion title="Where each level works">
    The four levels work in every product list: `/search/works`, the products of an affiliation, an author, a source or a geographic entity, their CSV and Excel exports, and the indicators (`plot`).

    In `/search/sources` and `/search/sources/filters`, `topics` only accepts topics (`https://openalex.org/T...`), which are compared with each source's topics. A domain, field or subfield doesn't return an error, but it returns 0 results.
  </Accordion>
</AccordionGroup>

### Find the identifiers

[`GET /search/works/filters`](/en/api-reference/search/works-filters) returns `topics` as a tree: each domain has its fields in `children`, each field its subfields and each subfield its topics. Every node has `value`, `title` and `count`, and the `value` of any of them works in `topics`:

```json
"topics": [
  {
    "value": "https://openalex.org/domains/2",
    "title": "Social Sciences",
    "count": 810297,
    "children": [
      {
        "value": "https://openalex.org/fields/33",
        "title": "Social Sciences",
        "count": 453028,
        "children": [
          {
            "value": "https://openalex.org/subfields/3304",
            "title": "Education",
            "count": 102372,
            "children": [
              {"value": "https://openalex.org/T14483", "title": "Education and Teacher Training", "count": 22593}
            ]
          }
        ]
      }
    ]
  }
]
```

As with the other filters, if you send `topics` to the filters endpoint, the tree only includes the branches that exist within that result.

### Example: products of a subfield

Products of the Education subfield published between 2020 and 2026, sorted by citations:

<CodeGroup>

```bash cURL
curl --get "https://api.impactu.colav.co/search/works" \
  --data-urlencode "topics=https://openalex.org/subfields/3304" \
  --data-urlencode "years=2020,2026" \
  --data-urlencode "sort=citations_desc" \
  --data-urlencode "max=10" \
  --header "Accept: application/json"
```

```python Python
import requests

response = requests.get(
    "https://api.impactu.colav.co/search/works",
    params={
        "topics": "https://openalex.org/subfields/3304",
        "years": "2020,2026",
        "sort": "citations_desc",
        "max": 10,
    },
    headers={"Accept": "application/json"},
    timeout=60,
)
response.raise_for_status()
for work in response.json()["data"]:
    topic = work["primary_topic"]
    print(topic["subfield"]["display_name"], "|", topic["display_name"])
```

</CodeGroup>

## Full example

Products published between 2020 and 2026, open access, with up to 10 authors, sorted by descending year, 20 at a time:

<CodeGroup>

```bash cURL
curl --get "https://api.impactu.colav.co/search/works" \
  --data-urlencode "years=2020,2026" \
  --data-urlencode "status=open" \
  --data-urlencode "authors_count=-10" \
  --data-urlencode "sort=year_desc" \
  --data-urlencode "max=20" \
  --data-urlencode "page=1" \
  --header "Accept: application/json"
```

```python Python
import requests

response = requests.get(
    "https://api.impactu.colav.co/search/works",
    params={
        "years": "2020,2026",
        "status": "open",
        "authors_count": "-10",
        "sort": "year_desc",
        "max": 20,
        "page": 1,
    },
    headers={"Accept": "application/json"},
    timeout=60,
)
response.raise_for_status()
result = response.json()
print(result["meta"]["count"], "results")
```

</CodeGroup>

## Go through all the pages

Compute the number of pages from `meta.count` and request them one by one:

```python
import math
import requests

URL = "https://api.impactu.colav.co/search/sources"
MAX = 250
params = {"max": MAX, "page": 1, "sort": "products_desc", "status": "open"}

first = requests.get(URL, params=params, timeout=60).json()
total_pages = math.ceil(first["meta"]["count"] / MAX)
items = first["data"]

for page in range(2, total_pages + 1):
    params["page"] = page
    items += requests.get(URL, params=params, timeout=60).json()["data"]

print(len(items))
```

## Common errors

Errors are returned with code `400` and a message in `error`.

| Cause                                   | Example                                |
| --------------------------------------- | -------------------------------------- |
| Invalid `authors_count`                 | `authors_count=0`, `authors_count=8-5` |
| Badly formatted `sort`                  | `sort=year:desc`                       |
| `geo_type` other than `city` or `state` | `/search/geo/country`                  |
| `max` out of range                      | `max=500`                              |

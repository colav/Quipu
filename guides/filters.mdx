Los endpoints de búsqueda (`/search/...`) comparten una misma forma de consultar. Esta guía te muestra cómo combinar sus parámetros.

## Los cuatro bloques de una consulta

| Bloque             | Parámetro              | Para qué sirve                     |
| ------------------ | ---------------------- | ---------------------------------- |
| Búsqueda por texto | `keywords`             | Buscar por nombre o título         |
| Paginación         | `max`, `page`          | Recorrer los resultados por partes |
| Ordenamiento       | `sort`                 | Definir el orden de los resultados |
| Filtros            | Varía según la entidad | Acotar los resultados              |

<Steps>
  <Step title="Busca por texto">
    Usa `keywords` para buscar por nombre o título. Para combinar palabras con OR, AND o NOT, mira la guía de [búsqueda semántica](/guides/semantic-search).

    ```text
    GET /search/works?keywords=colombia
    ```

  </Step>

  <Step title="Pagina los resultados">
    Usa `max` (de 1 a 250) y `page`. La respuesta incluye en `meta.count` el total de resultados y en `meta.cursor.next` la URL de la página siguiente.

    ```text
    GET /search/works?max=20&page=2
    ```

  </Step>

  <Step title="Ordena">
    `sort` usa el formato `campo_direccion`, donde la dirección es `asc` o `desc`.

    ```text
    GET /search/works?sort=year_desc
    ```

  </Step>

  <Step title="Filtra">
    Cada entidad tiene sus propios filtros. Para enviar varios valores, sepáralos con coma.

    ```text
    GET /search/works?years=2020,2026&status=diamond,gold
    ```

  </Step>
</Steps>

## Campos de ordenamiento por entidad

| Endpoint                      | Campos de `sort`                        |
| ----------------------------- | --------------------------------------- |
| `/search/person`              | `citations`, `products`, `h`, `h5`      |
| `/search/works`               | `citations`, `alphabetical`, `year`     |
| `/search/affiliations/{tipo}` | `citations`, `products`, `h`, `h5`      |
| `/search/sources`             | `citations`, `products`, `alphabetical` |
| `/search/patents`             | `alphabetical`                          |
| `/search/projects`            | `alphabetical`                          |
| `/search/geo/{tipo}`          | `alphabetical`                          |

<Warning>
  El valor de `sort` debe tener exactamente un guion bajo (por ejemplo,
  `products_desc`). Valores como `products_count_desc` o `year:desc` producen un
  error 400.
</Warning>

<Note>
  Si no envías `max`, `page` ni `sort`, se aplican `max=10`, `page=1` y
  `sort=citations_desc`. Los listados de patentes y proyectos solo se ordenan
  por `alphabetical`, así que envía `sort=alphabetical_asc` o
  `sort=alphabetical_desc` en ellos.
</Note>

## Filtros por entidad

| Endpoint                                                                      | Filtros                                                                                                                              |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `/search/works`                                                               | `years`, `product_types`, `status`, `topics`, `countries`, `authors_count`, `authors_ranking`, `groups_ranking`, `institutions_type` |
| `/search/affiliations/{tipo}`                                                 | `states`, `cities`, `groups_ranking`                                                                                                 |
| `/search/sources`                                                             | `source_types`, `scimago_quartiles`, `apc_range`, `status`, `publication_time`, `license_type`, `topics`                             |
| `/search/person`, `/search/patents`, `/search/projects`, `/search/geo/{tipo}` | Sin filtros                                                                                                                          |

## Descubre los valores válidos

Productos, afiliaciones y fuentes tienen un endpoint que devuelve las opciones disponibles de cada filtro, con la cantidad de resultados de cada una:

- [`GET /search/works/filters`](/api-reference/search/works-filters)
- [`GET /search/affiliations/{affiliation_type}/filters`](/api-reference/search/affiliations-filters)
- [`GET /search/sources/filters`](/api-reference/search/sources-filters)

Estos endpoints aceptan los mismos filtros que el listado. Si ya aplicaste un filtro, solo devuelven las opciones que existen dentro de ese resultado. El `value` de cada opción es el que debes enviar en el filtro.

## Formatos especiales

<AccordionGroup>
  <Accordion title="Rangos: years, apc_range y publication_time">
    Se envían como mínimo y máximo separados por coma.

    ```text
    years=2020,2026
    ```

  </Accordion>

  <Accordion title="Cantidad de autores: authors_count">
    Acepta cuatro formatos:

    | Valor | Significado |
    | --- | --- |
    | `5` | Exactamente 5 autores |
    | `5-` | 5 o más autores |
    | `-5` | Hasta 5 autores |
    | `5-8` | De 5 a 8 autores |

  </Accordion>

  <Accordion title="Tópicos y tipos de producto">
    Usa el `value` devuelto por el endpoint de filtros. En `topics` es la URL de OpenAlex de un dominio, área, subárea o tópico (por ejemplo, `https://openalex.org/T14483`; los detalles están en la sección siguiente) y en `product_types` lleva el prefijo de la fuente (por ejemplo, `impactu_Artículo de revista`).
  </Accordion>
</AccordionGroup>

## Filtrar por dominio, área, subárea o tópico

Cada producto tiene un tópico principal de OpenAlex (`primary_topic`), que pertenece a una jerarquía de cuatro niveles. El filtro `topics` acepta cualquiera de ellos, cada uno con su propia URL:

| Nivel   | En OpenAlex | Formato                               | Ejemplo                                                        |
| ------- | ----------- | ------------------------------------- | -------------------------------------------------------------- |
| Dominio | domain      | `https://openalex.org/domains/{id}`   | `https://openalex.org/domains/2` (Social Sciences)             |
| Área    | field       | `https://openalex.org/fields/{id}`    | `https://openalex.org/fields/33` (Social Sciences)             |
| Subárea | subfield    | `https://openalex.org/subfields/{id}` | `https://openalex.org/subfields/3304` (Education)              |
| Tópico  | topic       | `https://openalex.org/T{id}`          | `https://openalex.org/T14483` (Education and Teacher Training) |

Un nivel incluye todo lo que tiene debajo: filtrar por un dominio devuelve los productos de todas sus áreas, subáreas y tópicos. Con los ejemplos de la tabla, cada nivel acota el anterior:

```text
GET /search/works?topics=https://openalex.org/domains/2        810.297 productos
GET /search/works?topics=https://openalex.org/fields/33        453.028 productos
GET /search/works?topics=https://openalex.org/subfields/3304   102.372 productos
GET /search/works?topics=https://openalex.org/T14483            22.593 productos
```

Los conteos son de noviembre de 2026 y cambian con cada actualización de los datos.

<AccordionGroup>
  <Accordion title="Varios valores, incluso de niveles distintos">
    Separa los valores con coma. Se unen con **O**, así que el resultado incluye los productos de cualquiera de ellos. Puedes mezclar niveles: este ejemplo pide los productos del dominio Health Sciences o del área Social Sciences.

    ```text
    GET /search/works?topics=https://openalex.org/domains/4,https://openalex.org/fields/33
    ```

  </Accordion>

  <Accordion title="Junto con otros filtros">
    `topics` se une con **Y** a los demás filtros. Este ejemplo pide los productos del área Social Sciences publicados entre 2020 y 2026:

    ```text
    GET /search/works?topics=https://openalex.org/fields/33&years=2020,2026
    ```

  </Accordion>

  <Accordion title="Dónde funciona cada nivel">
    Los cuatro niveles funcionan en todos los listados de productos: `/search/works`, los productos de una afiliación, un autor, una fuente o una entidad geográfica, sus exportaciones a CSV y Excel, y los indicadores (`plot`).

    En `/search/sources` y `/search/sources/filters`, `topics` solo acepta tópicos (`https://openalex.org/T...`), que se comparan con los tópicos de cada fuente. Un dominio, un área o una subárea no da error, pero devuelve 0 resultados.
  </Accordion>
</AccordionGroup>

### Encuentra los identificadores

[`GET /search/works/filters`](/api-reference/search/works-filters) devuelve `topics` como un árbol: cada dominio tiene sus áreas en `children`, cada área sus subáreas y cada subárea sus tópicos. Todos los nodos tienen `value`, `title` y `count`, y el `value` de cualquiera de ellos sirve en `topics`:

```json
"topics": [
  {
    "value": "https://openalex.org/domains/2",
    "title": "Social Sciences",
    "count": 810297,
    "children": [
      {
        "value": "https://openalex.org/fields/33",
        "title": "Social Sciences",
        "count": 453028,
        "children": [
          {
            "value": "https://openalex.org/subfields/3304",
            "title": "Education",
            "count": 102372,
            "children": [
              {"value": "https://openalex.org/T14483", "title": "Education and Teacher Training", "count": 22593}
            ]
          }
        ]
      }
    ]
  }
]
```

Como en los demás filtros, si envías `topics` al endpoint de filtros, el árbol solo incluye las ramas que existen dentro de ese resultado.

### Ejemplo: productos de una subárea

Productos de la subárea Education publicados entre 2020 y 2026, ordenados por citas:

<CodeGroup>

```bash cURL
curl --get "https://api.impactu.colav.co/search/works" \
  --data-urlencode "topics=https://openalex.org/subfields/3304" \
  --data-urlencode "years=2020,2026" \
  --data-urlencode "sort=citations_desc" \
  --data-urlencode "max=10" \
  --header "Accept: application/json"
```

```python Python
import requests

response = requests.get(
    "https://api.impactu.colav.co/search/works",
    params={
        "topics": "https://openalex.org/subfields/3304",
        "years": "2020,2026",
        "sort": "citations_desc",
        "max": 10,
    },
    headers={"Accept": "application/json"},
    timeout=60,
)
response.raise_for_status()
for work in response.json()["data"]:
    topic = work["primary_topic"]
    print(topic["subfield"]["display_name"], "|", topic["display_name"])
```

</CodeGroup>

## Ejemplo completo

Productos publicados entre 2020 y 2026, de acceso abierto, con hasta 10 autores, ordenados por año descendente, de 20 en 20:

<CodeGroup>

```bash cURL
curl --get "https://api.impactu.colav.co/search/works" \
  --data-urlencode "years=2020,2026" \
  --data-urlencode "status=open" \
  --data-urlencode "authors_count=-10" \
  --data-urlencode "sort=year_desc" \
  --data-urlencode "max=20" \
  --data-urlencode "page=1" \
  --header "Accept: application/json"
```

```python Python
import requests

response = requests.get(
    "https://api.impactu.colav.co/search/works",
    params={
        "years": "2020,2026",
        "status": "open",
        "authors_count": "-10",
        "sort": "year_desc",
        "max": 20,
        "page": 1,
    },
    headers={"Accept": "application/json"},
    timeout=60,
)
response.raise_for_status()
result = response.json()
print(result["meta"]["count"], "resultados")
```

</CodeGroup>

## Recorrer todas las páginas

Calcula el número de páginas con `meta.count` y recórrelas una por una:

```python
import math
import requests

URL = "https://api.impactu.colav.co/search/sources"
MAX = 250
params = {"max": MAX, "page": 1, "sort": "products_desc", "status": "open"}

first = requests.get(URL, params=params, timeout=60).json()
total_pages = math.ceil(first["meta"]["count"] / MAX)
items = first["data"]

for page in range(2, total_pages + 1):
    params["page"] = page
    items += requests.get(URL, params=params, timeout=60).json()["data"]

print(len(items))
```

## Errores comunes

Los errores se devuelven con código `400` y un mensaje en `error`.

| Causa                                   | Ejemplo                                |
| --------------------------------------- | -------------------------------------- |
| `authors_count` inválido                | `authors_count=0`, `authors_count=8-5` |
| `sort` con formato incorrecto           | `sort=year:desc`                       |
| `geo_type` distinto de `city` o `state` | `/search/geo/country`                  |
| `max` fuera de rango                    | `max=500`                              |
